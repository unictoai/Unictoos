# Unictoos v0.4.2 Feature Boundaries

## Release intent

Unictoos v0.4.2 maximizes the functionality that can be delivered and verified inside the Android repository. Features that need a provider account, relay infrastructure, cloud storage, companion application, or physical USB hardware are represented by explicit contracts and capability-aware UI rather than fake controls.

## Verified implementation categories

| Feature | v0.4.2 treatment | Capability boundary |
|---|---|---|
| Scene-only configuration backup and restore | Implement locally | Imports scenes and layout metadata; destination credentials are never imported. |
| Exportable diagnostics and safe configuration | Existing local implementation | Credentials remain redacted or omitted. |
| Camera source selection, preview recovery, adaptive bitrate, recording, markers, recap history | Existing local implementation | Requires Android runtime permissions and compatible device APIs. |
| True multi-destination fan-out | Integration-ready contract only until the service wiring is proven | RootEncoder MultiStream must own multiple active outputs; no fake success state is permitted. |
| SRT transport | Integration-ready only if the bundled RootEncoder API exposes a stable SRT path | Must be validated against a real SRT listener; RTMP/RTMPS remains the verified path. |
| YouTube, Twitch, and Kick metadata APIs | Provider integration boundary | Needs user OAuth credentials and platform scopes; saved RTMP keys do not authorize metadata or chat APIs. |
| Chat, events, moderation | Provider integration boundary | Needs platform OAuth, event transport/webhooks, and platform-specific permission handling. |
| Cloud backup | Service boundary | Needs a selected storage provider, account, privacy policy, conflict model, and authentication. |
| Remote control | Service/companion boundary | Needs an authenticated local or remote WebSocket endpoint and pairing protocol. |
| SRTLA/RIST bonding | Native and relay boundary | Needs native transport support plus a compatible relay/server; it cannot be truthfully enabled by a UI toggle alone. |
| UVC/capture cards | Hardware boundary | Needs USB host permission, device-specific format negotiation, and physical hardware testing. |

## Connector audit

The current session has no Twitch or Kick connector and no user-provided provider credentials. The only YouTube search match is a disabled vidIQ connector, which is unrelated to livestream control. Therefore v0.4.2 does not claim OAuth chat, moderation, metadata, cloud backup, or remote-control functionality.

## Product rule

Every unavailable integration must be surfaced as either **Not connected** or **Integration-ready**, with the exact missing dependency named. The app must never report a destination, chat room, cloud backup, or remote controller as active unless a real authenticated session is established.
