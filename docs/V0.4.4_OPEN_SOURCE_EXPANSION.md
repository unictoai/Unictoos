# Unictoos v0.4.4 open-source expansion

## Goal

This release responds to the requirement that Unictoos should add the maximum useful feature set without a backend, paid API, OAuth server, cloud account, or relay service. The implementation prioritizes Android platform APIs, the already verified RootEncoder 2.8.0 path, and Apache-2.0 AndroidX Media3 components.

## Implemented locally

| Capability | Implementation | External requirement |
|---|---|---|
| MP4 trim/export | Media3 Transformer 1.11.0 creates a new trimmed local MP4 from Library | None; device testing with representative recordings is still required |
| Session analytics | Bounded SQLite database and local comparison card | None |
| Scene organization | Persisted source groups, transition mode, duration, and templates | None |
| Live controls | Camera switching, mute/record/stop notification actions, encoder telemetry | Android permissions and physical-device validation |
| Configuration portability | Scene-only import/export with secret isolation | None |
| Direct multistream | Bounded two-output RootEncoder adapter | Two valid destinations; physical network validation |
| SRT | RootEncoder SRT endpoint routing | A reachable SRT listener/server for interoperability testing |
| Advanced-audio policy | Bounds validation for future DSP profiles | Actual live PCM DSP is not silently claimed |

## Research conclusions

StreamPack is a mature Apache-2.0 Android broadcasting library with RTMP/RTMPS, SRT, MediaCodec, Camera2, file output, and modular streamer pipelines. RootEncoder is also Apache-2.0 and already powers Unictoos, with RTMP, RTSP, SRT, UDP, camera switching, filters, file sources, and MP4 recording. ScreenStreamerGo demonstrates a practical StreamPack screen-broadcast application but is GPL-3.0 and therefore was used only as a feature reference. Moblin provides ideas for quick controls and remote workflows but is an iOS application, not a drop-in Android module. AndroidX Media3 Transformer is Apache-2.0 and officially supports local trimming, effects, overlays, audio processors, and export.

The project retains RootEncoder instead of migrating the live capture engine to StreamPack because the existing service contains generation-safe MediaProjection and graphics-resource recovery work that is not safe to replace without a new physical-device test campaign. Media3 is isolated to post-session local editing and does not touch the live encoder path.

## Explicit non-local capabilities

OAuth chat, events, moderation, metadata, scheduling, cloud backup, remote control across devices, SRTLA/RIST bonding, WHIP signaling, and USB/UVC/HDMI capture need credentials, a paired peer, a relay/signaling endpoint, or physical hardware. These capabilities have contracts and capability-matrix entries but no fake local implementation.

Screen-plus-camera picture-in-picture requires multiple producer surfaces and a shared compositor feeding one encoder input. The current single-source RootEncoder path remains unchanged for stability; a compositor must be developed and physically validated as a separate media milestone.
